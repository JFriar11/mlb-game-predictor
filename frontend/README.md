# The pregame notebook

Repository-local React/TypeScript dashboard for the read-only FastAPI ledger.
Node 22.12+ is required. Use the committed `package-lock.json` with `npm ci`.

From the repository root:

```bash
make dashboard-install
```

Start the supported local PostgreSQL service if needed (`make postgres`). In one
terminal, start the API from the root using the already configured environment:

```bash
MLB_API_PORT=8010 .venv-sprint10b/bin/mlb-predictor-api
```

In another terminal, start the dashboard:

```bash
MLB_DASHBOARD_API_TARGET=http://127.0.0.1:8010 make dashboard-dev
```

Open `http://127.0.0.1:5173`. Both servers bind to loopback. API port 8000 is the
dashboard's default target; the example uses 8010 to avoid a service already on
8000 during acceptance. `MLB_DASHBOARD_API_TARGET` is Vite server configuration,
not a browser `VITE_*` secret or database connection string. The browser always
uses same-origin relative `/api` and `/health` URLs. No CORS relaxation is needed.

The real ledger currently has no saved predictions. The normal dashboard must
show that empty state; it never substitutes a demonstration automatically.

## Explicit demonstration

Use the visible **Explore the demo** button or open:

```text
http://127.0.0.1:5173/?demo=1&date=2026-08-14
```

This mode needs no API. A persistent banner labels all its numbers synthetic.
Its means and win probabilities are stipulated examples, not outputs from a
fitted model or real MLB forecasts. It does not write to any ledger or call the
API. The demonstration includes retained inputs, missing older evidence, and
lookup ID `8000003` for a game without a forecast. Return to recorded forecasts
using the banner's button. That transition changes the source, not the real data.

The tracked fixture is generated by `scripts/build_dashboard_demo.py` using an
in-memory SQLite database, the actual response models, and deterministic count
math. It makes no MLB requests or model loads. `tests/test_dashboard_contract.py`
verifies it against Python's current response contract. Regeneration:

```bash
.venv-sprint10b/bin/python scripts/build_dashboard_demo.py
```

## Interactions and scientific semantics

- Select an official game date, move backward/forward, or return to today. The
  default date and displayed timestamps use America/Chicago; official MLB dates
  retain their separate meaning. The URL retains date/game/demo state and supports
  browser back/forward navigation.
- Select a game or look up a positive MLB game ID. Discovered games without an
  official forecast differ from unknown IDs and unavailable storage.
- Means are labeled expected runs, not exact final scores. Charts and their
  accessible tables retain the censored **12+** label. Likely score bins are
  independent scoring categories, not resolved final scores.
- Toggle uncensored 80%/95% marginal ranges and inspect the model mass. Nominal
  mass is not advertised as measured real-world interval coverage.
- Read raw/stabilized lineup and opposing-pitching evidence, sample sizes and
  caveats, or an explicit missing-evidence state. These are not causal effects.
- Keep calibrated wins, deterministic input-quality flags, and retrospective
  calibration evidence separate. No composite confidence grade is invented.
- Inspect timing, versions, cutoff/source timestamps, starter IDs, and separate
  settlement outcomes. Latest discovery is identified as mutable context. If a
  captured team ID contradicts discovery, use the captured ID instead of silently
  relabeling the forecast with a different team.

Refresh is manual. Successful fetch time is shown independently of prediction and
source timestamps. A failed refresh can retain the same dated/game view with an
explicit stale warning. Changing date, game, or source clears old results; aborted
or late responses cannot replace the active view. Request timeouts are ten seconds.
Rendered fields are runtime-validated with Zod before display. Empty, loading,
invalid-response, API-error, missing-artifact, missing-evidence, and not-recorded
states remain distinct. No fetch performs a write or generates a forecast.

## Build and verification

```bash
make dashboard-build
cd frontend
PLAYWRIGHT_BROWSERS_PATH=0 npx playwright install --no-shell chromium
PLAYWRIGHT_BROWSERS_PATH=0 npm test
```

Playwright starts/stops a production preview on port 4173. It uses the supported
full-Chromium headless channel; the separate headless-shell bundle failed on the
local Mac. On Linux CI use `--with-deps --no-shell chromium` when installing.
Fourteen default browser checks use controlled responses or explicit demo data;
the separate real-API test is opt-in. With the API on 8010:

```bash
PLAYWRIGHT_BROWSERS_PATH=0 MLB_DASHBOARD_REAL_API=1 \
  MLB_DASHBOARD_API_TARGET=http://127.0.0.1:8010 npm test
```

Screenshots and failure traces are generated under ignored `test-results/`.
The suite covers interactions, request races, stale/error/empty states, settlement
and censoring, keyboard navigation, mobile reflow, and automated WCAG A/AA checks.
Automated checks do not establish full accessibility conformance or Safari/Firefox
compatibility. Those browsers and assistive-technology review remain release work.

The build passes with two third-party Zod/Rollup comment-annotation warnings;
Rollup removes those annotations. Backend tests retain the existing Starlette
TestClient deprecation warning. These do not prevent verification.

## Hosting boundary

`npm run build` produces static assets in ignored `dist/`. For local production
preview use `MLB_DASHBOARD_API_TARGET=http://127.0.0.1:8010 npm run preview` and open
`http://127.0.0.1:4173`. Vite's preview proxy is a local verification convenience,
not a production host. A deployed build needs an approved same-origin reverse
proxy to the FastAPI service. API/database credentials never belong in client code.

This milestone creates no Sites project, hosted URL, cloud resources, public
listener, authentication system, or registry upload. The existing Python Docker
image remains the API/CLI runtime; it does not embed the dashboard. Hosting,
authentication/network policy, monitoring, and frontend deployment packaging are
the next release milestone, subject to the existing infrastructure approval.

Implementation references: [Vite proxy configuration](https://vite.dev/config/server-options.html#server-proxy),
[React effect cleanup](https://react.dev/reference/react/useEffect), and
[Playwright web servers](https://playwright.dev/docs/test-webserver).

## Local lineup sandbox

Run `make sandbox VENV=.venv-sprint10b` from the root, then open
<http://127.0.0.1:8020/?sandbox=1>. This serves the built dashboard and explicitly
enabled inference API together. Load retained starting lineups or select players
by name, then predict a hypothetical matchup. The recorded notebook styling is
preserved. Inputs/results stay separate from official forecasts and are lost on
reload. See [sandbox guide](../docs/SANDBOX.md). Actual-model browser acceptance is
opt-in via `MLB_SANDBOX_REAL_API=1` with `MLB_DASHBOARD_BASE_URL` pointing at the
started sandbox; standard CI uses mocked sandbox responses and no private artifact.
